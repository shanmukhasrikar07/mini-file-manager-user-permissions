Background & Problem Definition

Problem Statement & The Two Security Blind Spots

The Multi-User Storage Challenge
  • Shared Infrastructure: Multi-tenant environments share underlying storage. Without enforced boundaries, users can read or delete unauthorized data.
  • Application-Level Simulation: We simulate Unix DAC with in-memory tree nodes and JSON persistence without altering OS kernels.
  • Central Choke Point: Every single CRUD command must pass through strict permission verification.
Two Blind Spots of Traditional DAC
❌ Blind Spot #1: Probing & Brute Force

Standard DAC silently denies unauthorized requests without alerting admins or stopping attackers.

Solution: Active Intrusion Detection & 120s Account Lockout.

❌ Blind Spot #2: Irreversible Overwrites

Standard DAC cannot recover from accidental overwrites by authorized users with write permissions.

Solution: Non-destructive File Versioning & Rollback.

System Architecture

Layered Architecture & Central Choke Point

1. Shell Layer (shell.py)

Interactive Unix-like CLI interface for user interaction.

2. Enforcement Layer (filesystem.py / permissions.py)

Central choke point for path resolution and 9-bit rwx checking.

3. Intrusion Detector (intrusion.py - NEW)

Sliding window event counter; flags and locks abusive accounts.

4. Version Manager (versioning.py - NEW)

Snapshots, diffs, and non-destructive rollbacks with SHA-256 checks.

Core Design Principles
  • Zero Shell Bypass: The shell never communicates with storage directly.
  • Unified Choke Point: Intrusion detection and versioning hook into the single check function, guaranteeing full coverage.
  • RBAC Roles: Admin (superuser bypass + recovery control) and Standard User (strict rwx enforcement).
  • Persistent State: Fully serialized to storage.json and users.json across reboots.
Data & Permission Model

Node Structure, 9-Bit Permissions & Resolution

Node Model & 9-Bit Octal Bits
  • Node Metadata: name, owner, group, permission, content, and bounded versions list.
  • 3 Classes: Owner (bit 6-8), Group (bit 3-5), Others (bit 0-2).
  • 3 Modes: Read (4), Write (2), Execute (1).
  • Directory Execute: Represents traversal permission. Path resolution fails if intermediate directories lack Execute bit.
Centralized O(1) Check Logic
def has_permission(node, user, requested): if user.role == 'admin': return True cls = ('owner' if user.username == node.owner else 'group' if user.group == node.group else 'other') shift = {'owner': 6, 'group': 3, 'other': 0}[cls] bits = (node.permission >> shift) & 0o7 return (bits & requested) == requested
⭐ Core Feature 1 (Section IX)

Intrusion Detection & Automatic Account Lockout

Active Defense Policy: Automatically detects unauthorized probing and protects against brute-force attacks.
THRESHOLD (N)

3 Strikes

3 suspicious events trigger lockout

WINDOW (W)

60 Seconds

Sliding time window for tracking

LOCK TIME (T)

120 Seconds

Active session killed & login disabled

Trigger Events:
  • Permission denials during cd, cat, write, chmod, etc.
  • Failed login attempts (tracked per attempted username).
NEW Admin Commands:
  • alerts: Review recent security flags and active locks.
  • unlock <user>: Manually clear lockout early with full audit entry.

⭐ Core Feature 2 (Section X)

File Versioning & Non-Destructive Rollback

Recovery Control: Automatically snapshots previous file versions on overwrite with cryptographic SHA-256 integrity validation.
BOUNDED HISTORY

K = 5 Versions

Retains up to 5 snapshots (FIFO eviction)

NON-DESTRUCTIVE

Undoable

Current content snapshotted before rollback

INTEGRITY CHECK

SHA-256

Asserts digest match before restoring

NEW Versioning Commands:
  • history <path>: Lists stored versions with author & timestamp.
  • diff <path> <v1> <v2>: Line-level difference display.
  • restore <path> <v>: Roll back file to version v safely.
Permission & Complexity Rules:
  • Versions inherit file permissions (read for history/diff, write for restore).
  • Storage complexity bounded strictly to O(K • s).

def write(self, path, user, data): node = self.resolve(path, user) require_permission(node, user, WRITE, 'write') if node.content != '': snapshot(node, user) node.content = data def restore(self, path, user, num): node = self.resolve(path, user) require_permission(node, user, WRITE, 'restore') v = find_version(node, num) assert sha256(v.content) == v.sha # integrity check snapshot(node, user) # save current before rollback! node.content = v.content

Critical Analysis

Advantages, Limitations & Future Roadmap

Advantages
  • Unified Prevention, Detection & Recovery.
  • Single permission choke point (zero bypass).
  • Tamper-proof SHA-256 verification.
Limitations
  • Single primary group per user.
  • Full copies instead of deltas.
  • Fixed static thresholds.
Future Roadmap
  • R/W file locking with deadlock detection.
  • Delta-based version diff storage.
  • Adaptive machine-learned thresholds.
Conclusion

  • Integrated Security Model: Successfully unified Unix-style Discretionary Access Control, active intrusion detection, and file versioning.
  • Active Defense (Section IX): Converts passive audit logs into active defense via automatic 120s lockout on 3 violations within 60s, paired with admin alert management.
  • Reversible Recovery (Section X): Capped 5-snapshot per-file versioning with cryptographic integrity and non-destructive rollbacks.
  • Robust & Verified: 100% pass rate across test suite scenarios with persistent JSON state.
